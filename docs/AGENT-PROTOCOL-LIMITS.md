# Agent protocol limits (P0-04)

Agent HTTP telemetry now uses typed envelopes and validated per-item fields. Device batches have at most 250 entries, metric batches at most 500, and the existing request body limit remains 1 MiB. Vendor device fields are retained only after a bounded JSON-shape check (64 KiB/item, depth 6, at most 256 fields/list elements and 4 KiB/string). Serials, IPs, MACs, timestamps, toner levels and page counters are checked before a batch writes to the database. `CreatedAt` for newly received device data uses server receive time, while `LastSeen` retains the reported timestamp.

Updated Agents split device/metric uploads by count and serialized size (at most 512 KiB per request). This matters when an installation has more than 250 devices. Existing Agents that send larger batches must be updated before enabling the new server version; the server rejects oversized batches rather than storing an unbounded subset. Fleet operators should monitor Agent upload errors during rollout.

Authenticated Agent HTTP traffic is capped at 120 requests and 16 MiB per minute per Agent. Device/metric writes are capped at 2,000 entries per minute per Agent. Agent WebSocket traffic is capped at 1,200 messages and 32 MiB per minute; message types have distinct size ceilings (heartbeat/device deletion 16 KiB; progress/end 32 KiB; proxy stream chunk 512 KiB). Buffered legacy printer responses retain the existing 8 MiB ceiling until streaming-only proxy transport is deployed. Each Agent has at most eight outstanding server proxy requests; Agent-side proxy work also has eight slots. A quota breach yields HTTP 429 or closes the WSS connection. Sustained fleet load needs sizing tests before raising these limits.

Server-issued commands are allowlisted to `check_update`, `cancel_update`, `force_update` and `restart`. Each command has a random ID, issue time and one-minute expiry; the Agent rejects duplicate, missing, unsupported, expired and future commands. Agent-issued `device_deleted` notifications use the same short-lived ID model. Replay caches are in-memory and limited to 1,024 IDs per Agent; after restart, the one-minute expiry remains the bound on replay. Signed update trust and the privileged updater are separate P0-06/P0-07 work.

The server rejects old `device_deleted` messages without IDs by default. For a controlled rollout only, configure `security.agent_protocol_legacy_until` (or `AGENT_PROTOCOL_LEGACY_UNTIL`) to an RFC3339 UTC deadline **no more than 14 days ahead**, for example `2026-10-01T00:00:00Z`, and upgrade Agents before expiry. The fallback accepts only messages lacking *both* ID and expiry, with a recent timestamp. An invalid modern ID cannot fall back to legacy handling. Remove the setting after migration.

The existing P0-01 mTLS identity binding is unchanged. The P0-09 ownership audit and P0-05 printer proxy network restrictions remain separate security tasks. No command execution or generic network primitive is added here.
